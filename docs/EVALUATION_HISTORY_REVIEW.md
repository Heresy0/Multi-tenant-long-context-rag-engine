# 企业知识库历代评估复盘

整理日期：2026-10-05。范围：本机保存的37份报告，包括16份早期检索/答案/负载报告、19份带UTC时间编号的分层报告，以及2份命名离线报告。没有重新调用模型、重评旧答案或修改业务代码、数据、题集及历史报告。

## 1. 结论与比较边界

当前完整实测：60道单轮自动通过58道（96.67%），24轮对话自动通过22轮（91.67%）；53道可回答题在融合及重排阶段均找齐标注证据，最终上下文52/53完整（98.11%）。所有已执行在线业务层没有运行错误。仍有历史规则误拒答、关键验收片段被上下文限额丢弃，以及两项多轮完整性/评分争议。

不能把不同版本的分数连成一条严格的算法提升曲线：

- 早期检索48题、独立检索32题、答案开发32题、技术答案11题和星海60题是不同测试集合。
- 旧检索主要按来源/片段相关性计算Hit@8；分层评估要求文档名和标注证据同时匹配，并区分融合、重排、最终上下文。
- 旧答案脚本的事实完整率主要针对可回答题；新单轮代理通过率包含拒答、必要来源及实际被引用证据检查。
- 旧答案开发v1→v3有6道题的required_facts变化，不能把83.33%→95.83%全部算作生成能力提高。
- 星海单轮题集有4种SHA-256前缀：b82f2851、277933af、e66bfc58、3a0c8ca8。后两次修订还涉及等价短语/来源评分口径；最新语料清单哈希由4c08dbb2变为dc365c12。
- 相同单轮哈希不保证多轮题、评分程序、模型、应用代码或索引相同。多数旧报告没有记录代码提交和评分器哈希。
- 所有自动分数是回归代理，不是人工语义准确率或生产安全认证。错误、未测试、局部冒烟、旧轨迹回放均不能冒充完整新实测。

报告编号采用UTC；下文核心时间线换算为北京时间。早期报告用created_at而不是文件修改时间：例如负载报告生成于2026-10-01，尽管文件之后被修改过。

问题与处理：

1. 引用过多、不相关来源：现有生成规则要求每个结论使用真正支持它的来源、权威正式资料优先、采用最少充分结论和引用；答案服务绑定实际上下文引用。报告显示来源precision由60%的3题冒烟到后续100%，但冒烟不能作为总体质量基准，且缺少逐次代码版本，无法精确分配各改动的因果贡献。
2. 字面短语导致假失败：v1中“至少48小时前通知”不匹配“至少提前48小时”，“累计工作已满1年”不匹配“累计工作满1年”，事实并非一定错误。v1→v3有6题必答事实标注变化，包括长句拆成角色/数值、删去比价记录/缓存复用要求等。即使调整有业务理由，也必须标记为口径改变。
3. 小样本代表性不足：独立技术集仅3道可回答题。100%可回答性或引用来源命中不能掩盖2/3事实完整率，也不能推广到复杂PDF、多轮和全部部门。

## 7. 性能和费用：已有数据能说明什么

- 旧steady负载报告：26次请求全部HTTP200，错误率0%、吞吐0.1469请求/秒，平均12.51s，P95 18s、P99 20s。门禁P95要求≤15s，因此报告passed=false；零错误不等于性能达标。样本26次，不足以证明企业生产容量。
