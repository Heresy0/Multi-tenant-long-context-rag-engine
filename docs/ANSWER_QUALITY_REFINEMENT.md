# 回答质量优化说明（2026-10-06）

基于完整题集报告 `20261005T170515621429Z` 和8题补充报告 `20261005T171442181040Z`，本轮优化计算、首次条件覆盖、重复补全和评分误判。不改权限、业务数据、文档索引或检索规模。

## 1. 计算结果由程序负责

涉及 `backend/app/knowledge` 下的 `answer_models.py`、`calculation_service.py`、`answer_service.py`、`prompts.py`。

原来：模型提出操作数和结果 → 程序复算 → 结果不一致就拒答。XH-E-049的来源、单位、间隔顺序、次数和时间前提均正确，但模型算成21:42:30，导致整体拒答。

现在：模型选择操作和来源操作数 → 程序核验 → 程序计算并生成受控结论。`result`可为null；如模型填写，仅作为审计猜测，不作为运算输入，也不能补齐缺失前提。18:00:00加30秒、2分钟、10分钟、30分钟、2小时，得到20:42:30。

通过核验后，模型原计算句被完整替换，不保留其错误时长或额外描述。诊断增加 `proposed_result`、`model_result_matches`、`corrected_model_result`。无效引用、伪造摘录、单位不符、序列遗漏/重排、次数混淆、币种混合或时间前提缺失仍拒绝。金额使用Decimal，跨日时间保留日期限定。

程序保证所选输入的来源检查和运算，不自动证明模型选择的操作数已语义完整。支持范围仍是时间累加、金额合计与差额，不执行模型代码或任意表达式。

## 2. 表格条件在首次生成前逐项展开

新增 `backend/app/knowledge/condition_requirements.py`；接入 `answer_coverage.py`、`answer_service.py`、`answer_validation.py` 和提示词。

Q编号仍是用户问题原文分段；E编号是本次已授权上下文中明确表格行的条件要点。例如D3条件题会包含：有可接受替代方案、不阻断核心流程、客户书面接受、明确修复日期后可验收。模型必须逐项关联结论，关联结论必须引用该条件的实际资料编号；缺编号或缺对应引用不能靠事后补全掩盖。

这不是按题号运行的规则：支持定义、条件、适用条件、前提、必要条件、处理、验收处理、审批要求等列，另用紧急采购、L7设备授权的独立样例验证。只展开条件问法明确提及的行；保持“或/除非/否则/任一”等逻辑整体，不把可选条件变为全部必需。

冲突版本、空字段、截断字段、说明类片段不猜测；重复行去重。最多新增16项，超限不偷偷丢掉部分前提，而回到原问题覆盖和既有兜底。清单加入原生成调用，不新增规划、检索或二次生成调用。

覆盖仍由模型声明，编号和引用检查不是独立语义证明。模型可能把细项关联到不完整的结论；首次事实评分、原文补全及人工审查仍需保留。抽取器也不是任意自然语言、区间或复杂表格的完整规则解析器。

## 3. 减少已答全答案的重复补全

修改 `backend/app/knowledge/answer_completion.py`。

预算按向量、关键词、融合、重排分别核对对应数量，不混用所有数字。完整回答还需要表中的BM25/RRF说明及跨库共享口径。明确的阶段数值/跨库口径冲突拒答；缺阶段或措辞不确定继续原文补全。XH-D-28首次答案已满足条件，现在不再追加整张配置表和未询问的权重。

根因只有在答案引用实际根因片段，并按顺序表达明确动作和结果机制时才跳过补全。只引用概述、只写“详见复盘”、少动作、否定动作或含不确定表述，不启用跳过。仅问根因时，原文补全剔除明确标注的尾部耗时句；同时问时间/影响时保留。

XH-D-MT-05-T2已说明创建新请求、生成新幂等键、服务端视为不同任务，不再重复根因和附加未询问的耗时。未知措辞仍走兜底；这是保守字面机制检查，不是通用语义蕴含判定。其他条件表格原文兜底未删除。

## 4. 修订评分误判，不降低标准

新增 `backend/app/evaluation/assertions.py`，接入 `metrics.py`。主题集生成器标注升级为 `2026-10-06-r6`；补充集仅FP-008修订为v2。

增加已审核的逐题否定同义表达：XH-E-052的“不等于自动删除”、XH-MT-08-T3的“不自动删除/不会把数据库记录一并删掉”、FP-008的“不应重新执行业务”等。问题、参考答案、必答事实和来源要求不变。

`fact_assertions`只对显式标注的事实启用有限否定/矛盾保护：“并非不自动删除”不能当成“不自动删除”通过；同时说“不自动删除”和“会自动删除数据库记录”不能仅凭关键词通过。其他事实不做全局否定改写。缺数字、错来源、引用不完整仍不能通过。

复杂否定、引述后反驳、条件范围、对象/数值绑定及忠实度仍需人工审查。`semantic_checks`和`forbidden_claims`仍是人工字段，没有伪装成自动语义评分。
