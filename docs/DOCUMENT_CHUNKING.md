# 文档清洗与切片：structured-v4

本版在现有按格式解析基础上增加保守清洗、统一片段用途、条件关联和 OCR 待复核提示。没有改变向量 + PostgreSQL BM25 + RRF + 重排的检索架构，没有增加模型调用、数据库表、权限或公开接口。

## 1. 新链路

入库：按格式解析 → PDF 保守清洗 → 标题/段落/表格/FAQ/代码识别 → 明确条件列表绑定 → 切片 → 统一用途和质量标记 → 业务版本元数据 → Embedding/关键词 → 原有 PostgreSQL 记录。

查询：已有授权和版本选择 → 重排 → 重新判定片段用途、正文优先 → 原有最终候选和上下文预算 → 回答及校验。分类不修改来源文本，也不扩大读取范围。

## 2. 两种类型不要混淆

| 字段 | 用途 | 值示例 |
| --- | --- | --- |
| chunk_type | 内容结构 | paragraph / list / table / faq / code / rule_group |
| evidence_role | 问答选材用途 | content / front_matter |

表格不一定是正文：仅包含文档编号、版本等字段的表格可以是说明信息。反过来，章节叫“文档说明”不代表可以删除；其中存在业务规则时仍是正文。包含说明和业务规则的混合片段保留正文优先级。

`chunk_quality.py` 同时用于入库和问答。识别 splitter 自己生成的“文档/章节/页码”包装，然后判断实际内容，兼容旧索引的 PDF 页码包装及“公司名称 | 内部资料”。包装只用于分类，不从数据库正文中删除。未知文本按正文处理；代码块不降为说明。

说明信息仍保留索引；明确询问文档编号、版本、生效日期等属性时仍保留原检索顺序。新字段不是权限、权威等级或语义正确性证明。

## 3. PDF 清洗更加保守

- 不再把任意纯数字行当页码删除，保留独立金额、年份和版本。
- 明确页码格式只在末尾两条非空行、且数字等于物理页码时删除。裸数字和无法确认的页码保留；封面偏移造成印刷页码与物理页码不同也不猜。
- 重复页边内容采用原数字精确比较，不把 550、650 或两个业务版本归一为同一行。
- 不删除包含数字、表格分隔、业务义务、条件、关键字段或句子标点的重复行。仅已识别的短说明信息或文档标题继续使用原有重复阈值；无法判断的重复短句也保留。
- 不把明确的说明段落与业务正文合并。已有跨页段落、页码范围、版面解析和表格解析保留。

这是启发式清洗，不是完整的版面语义识别。宁可残留少量噪声，也不基于重复删除已识别的重要业务信息。已被旧清洗删掉的内容无法在查询时恢复，需要重新解析来源。

## 4. 规则切片与表格

普通段落仍使用原有 450 字符/60 重叠（TXT 为 500/50），表格和 FAQ 保留原有 900 字符目标。

- 含明确条件、义务或例外标记，且不超过 900 字符的段落保留为一块，避免机械地在 450 字符处拆开前置条件和例外。
- 不超过 200 字符、以冒号结束的明确规则引导句，与同章节紧跟的列表组成 `rule_group`。不跨章节或表格猜测关联。
- TXT 识别明确的项目符号/带标点编号列表，DOCX 识别 Word 的 List 样式；FAQ 内的列表仍留在问答对中。MD 和 PDF 使用原有列表识别，各格式统一绑定明确条件引导句。
- 较长的条件组仍切分，每个子块重复原始引导句、共享 parent_key；不保证无限长列表的所有条件都进入同一个块，也未增加父块自动回填。
- PDF 条件组保留起止页码及参与解析方式，跨页 OCR 部分仍标记待复核。
- DOCX 表格不再删除所有单元格空白，而是压缩为一个空格，避免把 `Bearer access_token` 等值粘成不同字符串。大表仍按完整行切分并重复表头；极长单行不强行截断。

这里没有模型生成的“规则摘要”，也没有把仅包含某个条件的子块认证为完整业务规则。D3 题已经完整提供表格却被模型漏答条件的问题，仍需要回答阶段改进。

## 5. OCR 质量与存储

分块的 metadata_json 新增：

```json
{
  "evidence_role": "content",
  "cleaning_version": "conservative-v1",
  "quality": {
    "review_required": true,
    "review_reasons": ["ocr_unverified"]
  }
}
```

只要解析链包含 OCR，就标记待人工复核。文档 metadata_json.quality 汇总 OCR 分块数、说明分块数和待复核状态。非 OCR 的 review_required=false 只表示没有本版定义的 OCR 警告，不表示内容已验收。

保留 OCR 原文，不猜改人名、金额或日期；没有伪造 OCR 置信度，没有新增人工确认入口，也没有默认阻止 ready 文档参与检索。扫描件“周宁→周末”仍需要对照原件核查和定点纠正，不能因出现新标记就认为已经修复。

诊断 trace 的候选和 context 会保留质量/解析/清洗字段，只在已有 opt-in 过程记录内使用；公开回答和引用格式不变。真实 trace 包含授权片段，应按内部资料保管。

## 6. 如何生效

1. 查询时 PDF 说明分类修复兼容旧切片：更新应用进程即可，不要求重新生成向量。
2. 数字保留、条件关联、表格空白和持久化质量字段属于入库变化：要重新解析并索引受影响文档。
3. 切片版本升为 `structured-v4`。主动再次执行原有入库流程时，旧 v3 索引不再被误认为已使用新策略；普通问答不会自动重建索引。重建仍调用 Embedding，可能消耗额度。
4. 所有新增字段写入已有 JSON 元数据，不需要新增 Alembic 迁移。更新容器时仍执行项目原有启动迁移，不要删除数据库卷。

Docker 更新应用：

```powershell
docker compose up -d --build api worker
```

本地只读检查，不入库、不生成向量、不调用付费模型：

```powershell
.venv\Scripts\python.exe scripts\inspect_document_chunks.py "文件的完整路径.pdf"
```

默认仅打印结构和质量；加 `--show-content` 才打印正文。扫描 PDF 仍需要本地 OCR 工具；无可用工具时会报错，不伪装解析成功。不要把包含内部正文的输出提交 GitHub 或上传知识库。

## 7. 验证范围与限制

回归覆盖 PDF 包装、混合正文保护、金额/日期保留、重复规则保护、OCR 标记、条件列表、表格空格、两种入库路径 JSON 持久化、旧版本重建、引用和原预算约束。

海岚验收题用本地旧重排记录只读重放：现在“客户已签署最终验收”能进入上下文，同文档仍最多 4 块、总预算仍 12000 字符。没有把企业专有文字写进通用分类规则；敏感 trace 不提交，另有独立合成回归保证 CI 可验证。

本次验证：优化前完整离线回归 437 项通过；最终版本 491 项通过，22 项外部集成测试被排除，编译及 `git diff --check` 通过。两个现有依赖的弃用警告未作为功能失败处理。

复用 20261004T173241439459Z 的旧重排结果，对 53 道可回答题只读重建上下文，完整证据通过从 50/53 变为 51/53；唯一状态变化为 XH-031 从不完整变为完整，其余题无完整证据状态退步。另对本地海岚 PDF 实际解析确认能产生片段用途与质量字段。以上没有调用模型、写业务数据库、重建向量或执行新在线题集。

不保证恢复未被检索召回的正文，也不保证解决所有正文相关性排序问题。历史差旅误解、计算输入契约、多轮追问偏移和同义评分问题不在本版修复范围。离线测试和旧轨迹重放不是新一轮真实模型评估，不能据此宣称准确率提高。
