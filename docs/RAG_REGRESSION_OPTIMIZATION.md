# 最新评估问题的定向优化（2026-10-05）

本次针对 `20261004T200546153084Z` 报告：单轮51/60，多轮16/24。把真实错误与关键词、来源评分误判分开处理，不删除失败题，不降低验收条件，不更换模型，不新增常规大模型调用。代码修改和离线回归不等于容器已更新或在线准确率已经提升。

## 1. 历史追问的业务时间

新增 `backend/app/knowledge/temporal.py`，由版本选择与追问改写共同使用。

例如“截至2026-10-04，普通员工2025年去上海的标准？”中，前者是查询日期，后者是业务年份。筛选区间现在是2025-01-01至2025-12-31，不能因为查询发生于2026年而筛掉历史版本。支持中文年月、年月日及横线/斜线日期；多个业务时间不擅自裁决比较范围。只问截至某日而没有业务日期时，仍使用该截至日期；当前时间默认按北京时间。

`ConversationResolver` 提示词明确新时间覆盖旧时间，不沿用历史拒答理由。模型改写后再做受限清理：只有当前追问明确给出业务时间、改写保留该时间、且用户没有主动给出截至日期，才去掉继承的截至日期。不增加一次改写调用；不能保证修复所有代词或时间理解错误。

## 2. 完整性与未来规则

`answer_constraints.py` 为原有答案生成增加检查提示：历史版本、表格定义与处理条件、总次数与追加次数、是否含首次、每路/融合/重排预算及共享范围。仍然只调用原有的一次结构化答案模型，不做常规二次润色。

对显式询问编码规则（如D3、A2）的允许/验收条件，在已经引用的“定义 + 处理”表格中找到唯一完整行时，可复制该行补足条件，并使用同一引用。模型没有引用的表格、冲突行、未问的编码、计算结论和拒答不补。明显声称无须条件却与条件行矛盾时拒答。这是限定的表格完整性保护，不是通用的语义正确性证明器；没有编码的复杂条件仍依赖生成和人工审查。

对“未来某期公司已经确定/承诺的规则”增加保守检查：需要原文明示覆盖整个未来期间的有效区间，或已公布的未来生效版本。现行、无截止日期的制度不是未来承诺；复审日期也不是失效日期。证据不足时在答案生成前拒答，不把2027年的限额肯定为今天的数字。未知有效期、复杂承诺语义仍可能需要治理元数据和人工判断。

## 3. 编号题的正文补取

`evidence_expansion.py` 在问题包含明确 `INC-年份-编号` 且已有候选包含同一完整编号时，补取该候选文档的前8块。最多2份文档、16块；数据库查询限制租户、可读库、文档ID、ready状态及块序号。

合并后去重，仍最多30个共享候选进入原有重排，最终最多8块，保留原有上下文字符预算和每来源最多4块。没有编号或没有授权命中文档时不补取；不会读取整个知识库，不增加Embedding或生成调用。它可改善“标题带事件号，耗时/根因在另一块”的情形，但不保证恢复第8块以后的正文，或在原候选没有该事件时找回事件。

诊断记录新增 `expanded_candidates`，便于区分融合阶段未召回与补取/重排/上下文丢失。受限计算失败记录增加结构化建议输入，仍仅在显式开启私有过程记录时收集，不暴露为普通问答接口。

## 4. OCR 姓名更正

对扫描维护通知第1页完整渲染图进行视觉核查，确认验证负责人为周宁。原文件不改写，也不修改题集真值。

`ocr_review.py` 使用可信配置 `reviewed_ocr.json`：文件SHA-256、页码、完整带标签的误识别短语、校对文本、核查者及日期共同约束。仅这份文件、这一页且短语唯一匹配时，在切分前更正“验证负责人: 周末”为“验证负责人: 周宁”；普通“周末值班”不受影响。核查记录标为 `codex_visual_check`，不是冒充人工批准。变化后的文件或未匹配文本不猜测更正。

受影响分块保留更正记录、原OCR页文本哈希和原文件哈希；原件可用于复查。仍保留 `ocr_unverified` / `review_required`，因为只核查一个字段，不代表所有姓名、日期和数字已验收。没有新增前端审核页或审核API；不能让上传文档自行声明核查结果，生产用的审核配置需按可信配置控制。

索引记录新增 `ocr_review_revision` 到既有JSON元数据，避免同文件同切片版本被误判为无需更新。更正后正文同时用于Embedding与BM25关键词，不在回答末端临时改姓名，也不只修改一个搜索通道。不新增数据库表或Alembic迁移。只有这份扫描件需要针对性重新索引，其他问答逻辑不要求30份全部重新入库。

## 5. 评分修订与复测

题集标注为 `2026-10-05-r3`，仍保留60道单轮、8组24轮对话、7道不可回答题、30份原文覆盖。

- `fact_alternatives`：逐题审核的等价短语，如“不相同”支持“不同”，只在指定题生效。不全局替换否定词。
- 数字边界：“2次”不匹配“12次”，“1.4”不匹配“1.40”。这仍是短语代理，不能自动验证所有角色与数字的对应关系。
- `accepted_source_document_sets`：必须满足某一整套充分来源，不能拼凑两套不完整来源。
- `accepted_evidence_sets`：有上下文时，替代证据还须在实际引用的片段内，引用编号、块ID、库ID仍要一致。API正式手册可替代FAQ支持API次数，但不能缺少Webhook规范。
- HTTP多轮没有正文快照时只能核对事实短语和来源代理；语义正确性、忠实度仍需人工审查。旧HTTP基线脚本保留原逻辑，本次能力使用统一 `evaluate_system.py`。
